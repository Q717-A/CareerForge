# Truth Engine — 分阶段事实可信度管理

## 阶段一：显式事实等级

这版为每条事实增加可选 `truth_status`，与原有的 `verification_status`（已确认 / 待确认 / 已过期 / 不采用）分开保存：

- `VERIFIED`：经过人工核查且留有来源的事实
- `REFRAMED`：有对应原始事实的措辞加工；对外陈述不得超过原始事实
- `INFERRED`：AI 推断，待核查
- `LEARNING`：正在学习、尚未完成的经历或技能
- `UNVERIFIED`：目前缺乏可靠验证的陈述

明确标记为 `INFERRED`、`LEARNING`、`UNVERIFIED` 的内容，不能改为“已确认”或进入 AI 生成所用的已确认事实基线。标记为 VERIFIED / REFRAMED 且确认为正式事实的条目，至少必须登记证据定位信息。

Project Lab 转入台账的草稿强制为 `UNVERIFIED + 待确认`，不能借项目“已实现”状态绕开个人事实审查。

## 兼容原则及尚待完善的部分

- 旧版事实保持 `NULL` 未评级，**不自动升级为 VERIFIED**；为避免突然破坏用户原有简历，旧版“已确认”的事实暂时仍沿用原生成行为。
- 用户可以在台账编辑窗口逐条标记可信等级。
- 事实等级仅依赖用户登记的来源定位信息；系统**尚不能自动证明附件、代码、项目成果与描述逐字相符**，不能把来源字段等同于独立审计。
- 不会直接检验任意生成简历的每一个句子及其事实引用；完整句级证据映射和最终导出阻断属于后续纵向切片。
- 请勿在公用 GitHub 仓库或提交记录里上传带真实个人隐私的主简历、招聘网站 Cookie 或模型密钥。
