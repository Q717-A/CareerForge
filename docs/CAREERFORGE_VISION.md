# CareerForge 产品愿景

CareerForge 是一个**本地优先、事实约束、以真实求职结果为目标的 AI Career Agent**。

它不是只负责“把简历写漂亮”的单点工具，而是把以下链路放到一个可追溯的工作台里：

1. 维护一份完整的 Master Profile / Master Resume；
2. 搜集并整理目标岗位；
3. 把 JD 拆成硬性条件、核心能力、加分项和证据要求；
4. 用事实库逐条判断“已经具备 / 只是没写 / 可以补齐 / 真实缺口”；
5. 针对每个岗位生成独立简历，但**不允许凭空增加经历、技能、数字成果或项目**；
6. 对真实能力缺口创建可完成的学习/项目计划；
7. 只有完成、验证、能讲清楚的项目，才允许进入正式简历；
8. 记录每次投递、面试与结果，让后续求职决策越来越有依据。

## 三条产品红线

### 1. 事实和表述必须分离

AI 可以重写表达、调整结构、针对岗位改变强调重点，但不能改变事实本身。

后续 Truth Engine 会把对外表述分成五类：

- **VERIFIED**：有可核对事实或证据，可以进入正式材料；
- **REFRAMED**：基于 VERIFIED 事实重新包装，事实没有发生改变；
- **INFERRED**：AI 做出的合理推导，必须经用户确认后才能升级；
- **LEARNING**：用户正在补齐的技能或项目，只能用于学习计划；
- **UNVERIFIED**：缺乏依据，禁止进入正式简历。

### 2. “推荐项目”不等于“做过项目”

CareerForge 可以根据岗位缺口设计项目，但项目默认只能进入 Project Lab。

只有当用户完成实现、留下证据、写出结果，并能回答核心面试问题后，项目才能进入“可写入简历”状态。

### 3. 自动化必须保留人工决策点

岗位采集、JD 分析、简历改写可以高度自动化；真正对外提交、带有不确定事实的内容、以及重要身份信息的使用，默认保留用户确认。

## 相比上游 ResumeForge 的新增方向

CareerForge 继续沿用 ResumeForge 已有的本地 SQLite、事实台账、岗位、简历、投递、面试和导出基础能力，在此基础上重点增加：

- **Job Radar**：多来源岗位发现、去重、归档和人工筛选；
- **Truth Engine**：事实级来源、状态、证据和导出闸门；
- **Project Lab**：把岗位能力缺口转换为真实可完成的学习项目；
- **Role-specific Resume Tailor**：按岗位选择事实、重组表述，而不是“一份简历改关键词”；
- **Evidence Graph**：让简历中的关键主张能够回指原始事实、项目结果或其他证据；
- **Career Feedback Loop**：把投递/笔试/面试结果反哺下一轮岗位选择和简历生成。

## V1 成功标准

V1 不追求无人值守海投。第一阶段成功标准是：

> 用户维护一份通用资料 → 选择一个目标岗位 → 系统解释岗位要求 → 指出事实证据和真实缺口 → 生成针对性简历 → 对缺口创建 Project Lab 项目 → 项目完成验证后再进入事实库和简历。

这个闭环跑通后，再扩展自动岗位采集和自动投递。
